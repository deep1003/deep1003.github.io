Policy Commons data curation workflow

A numbered, provenance-preserving workflow for cleaning locally collected Policy Commons records before integration into the iCloud master.

Method status: version 2.2, 19 September 2026. The previously reviewed protocol is retained below. This revision documents the executed rules and their limitations; it does not claim a new independent review or that every protocol requirement has been implemented.

Workflow overview

Read the protocol and implementation separately. The numbered sections specify the intended curation standard. The implementation snapshot records what the current scripts actually executed, the resulting counts and outstanding work. Protocol validation targets are not measured accuracy claims.

Implemented duplicate resolution

The script selects an identity key in this order: Policy Commons identifier, DOI, normalised URL, then a hash of normalised title, publisher, year and language. It groups by the selected namespace and key. Conflicting normalised titles within an identifier, DOI or URL group are split. The anchor is selected by completeness of title, abstract, year, publisher and URL, followed by secondary metadata completeness and abstract length. Missing fields are filled from the same group and their source observations are recorded.

Implementation limits. This is not exhaustive cross-identifier entity resolution. It does not establish that all translations, revisions or repository copies have been identified. The fallback composite key is used for grouping in the current script, whereas the stricter protocol below requires review of weak matches. The full compatibility checks and 99.9% precision target below have not been demonstrated for this release.

Implemented broad AI screening

A supported expression in the title produces core_ai; a match in the abstract or keywords produces substantive_ai. Both are retained. These labels describe lexical evidence, not a validated assessment of substantive relevance. Ambiguous abbreviations without a supported expression produce unresolved_ai.

Historical vocabulary remains incomplete. The current dictionary includes 지능형, 기계학습, machine learning and neural network, but does not explicitly include 머신러닝, 머시러닝, 기계 학습, 전문가 시스템, expert system, knowledge-based system or intelligent system. These are proposed expansion candidates requiring contextual checks, especially for earlier decades. The 84,438 count does not include a rerun with this expanded dictionary. Recovering omissions requires rescreening the 300,555-record canonical corpus where recoverable, not just the retained subset. No assumption is made that one terminology uniformly characterised the 1990s.

Non-AI meanings. Exclusion requires strong alternative-meaning evidence without explicit computational AI evidence. Biological neural-network exclusions require biological context in the title and no computational signal. Non-AI LLM and GPT expansions are also checked. Avian influenza and air-quality mentions alone do not trigger exclusion because AI may be applied in these domains. Of the retained records, 1,050 biological/computational ambiguity cases and 76 air-context ambiguity cases remain flagged for review.

For international organisations, EU bodies and multinational issuers, the script uses country aliases in the issuer name, or a local-office marker corroborated by publication place, to propose a local issuing-country link. This heuristic does not verify the legal entity, co-issuing role or local-office authorship. Country and regional names may be ambiguous and require review. Language and subject-country evidence do not overwrite issuer_country.

Each typed link stores the document identifier, attribution type, country code, whole-count value, method, confidence and evidence field/value. The unique key is (record_id, attribution_type, jurisdiction_code). A second view combines evidence types into one (record_id, interest_country) row with value 1. A document linked to Korea and the United States contributes 1 to each; repeated evidence for Korea still contributes only 1.

Analytical use. The 40,058 documents labelled resolved have at least one signal of any type. The 44,038 union pairs measure broad country relatedness, not verified national publication output. Use issuer links for issuing-country analysis and report target, publication-place, affiliation and language evidence separately or as sensitivity variants. Rule-based confidence labels are not calibrated probabilities. Documents linked to 20 or more countries require specific review before analytical use.

1. Freeze and inventory the local collection

Begin with every Policy Commons RIS, CSV, JSON, JSONL, database and archive stored locally, particularly under /Users/deep1003/Downloads. Resolve symbolic links and cloud-backed aliases before counting so the same physical file is not inventoried twice.

  1. Record path, real path, file type, byte size, modification time, SHA-256, hydration status, record count, query, module, page, year partition and collection category.
  2. Assign each raw occurrence the immutable key (source_file_sha256, source_record_ordinal).
  3. Retain raw bytes or a raw-record hash, parsed-record hash and normalised-content fingerprint.
  4. Freeze a read-only snapshot before any parsing, matching or exclusion begins.

Outputs. local_file_manifest, local_file_integrity_report, local_collection_category_registry and a snapshot manifest with run ID and timestamps.

2. Validate parsing and contamination

Structural and record-pair integrity must pass before records can be linked or classified.

  1. Validate RIS TY/ER boundaries, encoding, empty records, truncation and unexpected field drift.
  2. Check repeated IDs for conflicting titles, abstracts, typed dates, publishers and URLs.
  3. Detect title-abstract shifts by comparing adjacent records in original export order.
  4. Flag identical long abstracts attached to unrelated IDs and identical titles with materially incompatible abstracts.
  5. Validate a reproducible stratified sample against Policy Commons pages or original publisher documents.

A confirmed sequential shift, repeated abstract mismatch, parser-truncation pattern or export-order corruption quarantines the entire source batch. Release from quarantine requires reparse, frozen-sample revalidation, reviewer identity, evidence, parser version and result. No quarantined observation enters matching, enrichment or classification.

Outputs. source_batch_quarantine, record_integrity_flags, accepted-batch registry and contamination audit report.

3. Parse, normalise and preserve provenance

Parsing creates a source-observation layer rather than a prematurely merged master. Raw values are never overwritten.

  1. Parse fields into namespaced observed values while preserving original strings and order.
  2. Apply versioned normalisers for identifiers, URLs, Unicode text, organisations, languages and typed dates.
  3. Store one row per parsed occurrence in source_observation and one row per value in field-level provenance.
  4. Represent missing, malformed, conflicting and unavailable values with explicit reason codes.
  5. Retain every discovery route in source_collection_route, keyed to source_observation_id; canonical category views are derived from these occurrence-level records.

Outputs. source_observation, raw and normalised field tables, source_collection_route, parser report and normaliser-version manifest.

4. Resolve document identity, versions and duplicates

The analytical deduplication unit is a document version: the same intellectual content in the same language, edition and revision. Each parsed export row is a source_observation. Provider IDs and hosting URLs identify observations or platform items; they do not by themselves define the analytical entity. Verified publisher and repository copies of the same version may share one canonical_record, while translations, abridgements, revised editions and substantive updates remain separate records connected by typed relations. Raw downloads are immutable and are not deleted by this procedure.

Precondition: contamination gate

Records are not merged until title, abstract, typed dates, publisher and URL are shown to belong together. Repeated identifiers with conflicting content, shifted title-abstract pairs, truncated RIS records and systematic export-order errors are quarantined before entity resolution. A confirmed sequential shift, repeated mismatched long abstract, parser-truncation pattern or export-order corruption quarantines the entire source batch. No observation from that batch may enter matching, field completion or AI classification until it is reparsed and a frozen validation sample passes. Quarantine release records the evidence, reviewer, parser version and revalidation result.

Hard vetoes. A reused or cross-namespace ID, incompatible title or abstract, different language or edition, substantive revision, conflicting date type, or URL resolving to a collection page blocks automatic merging and creates an id_conflict or quarantine record.

Canonical record and field survivorship

The canonical anchor is ranked by structural validity, valid identifiers and URL, completeness of title, abstract, typed dates and publisher, richer secondary metadata, and preference for direct source metadata over generated summaries. A newer retrieval is only a tie-breaker. Field completion occurs only after identity is accepted. Values are never borrowed from translations, revisions, work-cluster relatives or merely similar candidates. Conflicting non-empty values remain explicit alternatives. Each selected field stores its source observation, original value, normaliser version, rule, decision status and conflict flag.

Versioned normalisation

Normalisers are frozen and versioned. DOI processing lower-cases and removes resolver prefixes after registry validation. URL processing normalises scheme and host case, removes fragments and tracking parameters, preserves content-bearing parameters and stores redirect targets with retrieval time. Titles use Unicode NFKC, controlled whitespace and punctuation handling, and language-aware rules. ISBN checksum, edition compatibility and organisation authority IDs are validated. Binary SHA-256 is strong mirror evidence; extracted-text hashes and similarity measures generate candidates only because OCR and templates can distort them.

Required outputs and tests

  • canonical_record: one accepted manifestation per record_id.
  • record_source_link: every raw occurrence linked to its canonical record.
  • duplicate_record_map: source record, canonical record, match rule, evidence and review status.
  • work_relation: typed translation_of, revision_of, abridgement_of, supplement_to and mirror_of relations with evidence and review status.
  • field_survivorship: selected and conflicting values with field-level provenance.
  • id_conflict, match_candidate, match_decision and source_batch_quarantine: reversible evidence for blocked and accepted decisions.

Each candidate follows a deterministic state machine: candidate to auto_accept, review_pending, accepted, rejected or conflict_quarantine. A source observation maps to at most one canonical record per method version; mappings cannot self-link and reruns with the same snapshot and configuration must be identical.

Validation reports pairwise precision, recall and F1, cluster-level over-merges and under-merges, false-merge severity, rule-specific results and 95% confidence intervals by language, period, issuer and missingness. The frozen test set is never used for tuning. Automatic merging requires at least 99.9% precision with its numerator, denominator and confidence interval reported; an inadequately sized test leaves that rule in review-only mode. Ambiguous pairs are independently coded by two blinded reviewers and adjudicated. Deduplication therefore produces a reversible analytical view, not destructive deletion.

5. Enrich missing evidence-bearing metadata

Recover missing title, abstract, language, identifiers, issuer candidates, publisher and original-document links only from accepted source observations, official pages or original documents. Enrichment fills evidence needed by later classifiers but never assigns AI relevance, genre or policy labels.

  1. Retain observed, normalised, inferred and manually verified values separately.
  2. Store source observation, evidence URL, access time, extraction method, confidence and missingness reason for every completed value.
  3. Never overwrite conflicting non-empty values or borrow fields from translations, revisions or similar documents.
  4. If new evidence changes an identity decision, start a new method-version rerun from Step 4 instead of retroactively mutating the earlier run.

Exit gate. Required classification fields have evidence-tier and missingness codes; conflicts and unsupported fields remain explicit. Output is a versioned enrichment layer linked to, not replacing, source observations.

6. Classify AI / Non-AI relevance

AI relevance and policy eligibility are independent axes. AI relevance uses only evidence about whether AI is substantively discussed; it must not use issuer type, policy genre or the presence of recommendations as model features. A technical paper can be centrally about AI but policy-ineligible, while a government report can be policy-eligible but non-AI. Inclusion in the primary country-policy master requires an AI label of core or substantive, an eligible policy label, and a separately resolved issuer jurisdiction.

Evidence used

Classification uses the title, abstract or summary, controlled keywords and available full text, with language-aware normalisation. Evidence follows this order: original full text, original publisher abstract or summary, Policy Commons generated summary, controlled keywords, then retrieval query. Generated or AI-enriched metadata is flagged and cannot be the sole basis for inclusion or exclusion. Every decision retains the supporting span, source rank, field-level language, translation status, OCR quality, rule or model version, score, threshold, reason code and review status.

Ordered decision tree

  1. If usable evidence is insufficient, contradictory or OCR-damaged, assign unresolved.
  2. If adequate inspected evidence affirmatively shows no genuine AI discussion, assign non_ai.
  3. If AI appears only as an example, generic list item, peripheral tool or isolated reference, assign incidental_ai_mention.
  4. If at least one substantive section or recurring analysis concerns AI but the wider document remains about another subject, assign substantive_ai_component.
  5. Assign core_ai_policy only when the declared purpose and main questions, findings or conclusions centrally concern AI.

Decision precedence is unresolved, non_ai, incidental_ai_mention, substantive_ai_component, then core_ai_policy. Removing the AI passages is used as an operational counterfactual: if a main question, finding, conclusion or substantive section would materially change, the record is substantive or core rather than incidental.

Multilingual and historical controls

Language and script are detected by field. Rules retain original and translated evidence and handle Unicode normalisation, CJK segmentation, Arabic and Persian morphology, transliteration and code-switching. Unsupported language-model combinations and low-quality machine translations are unresolved. Controlled lexicons are language- and version-specific and include false friends. Time-versioned terminology covers expert systems, knowledge-based systems, machine intelligence, cybernetics and early neural-network language when context establishes AI; generic algorithms, automation, robotics and data processing are never equated with AI automatically.

Decision pipeline

  1. Run multilingual high-precision inclusion and exclusion rules.
  2. Evaluate title-abstract-keyword consistency and reject contaminated field pairings.
  3. Apply a versioned and calibrated semantic classifier only to records whose evidence tier permits it.
  4. Route abbreviation ambiguity, missing abstracts, conflicting evidence and boundary scores to manual review.
  5. Apply the document-genre and policy-eligibility gate separately after AI relevance is assigned.
  6. Freeze exclusion evidence before any deletion-candidate manifest is created.

Validation and release gate

All training, development and frozen-test partitions are separated at work_cluster_id level, including duplicate, translation, edition and revision families. Thresholds are fixed before the frozen test. Performance is reported by class, language and script, period, evidence tier and document genre, with sampling-weighted estimates, work-cluster metrics, macro and worst-group results, and 95% confidence intervals. Reviewers are blinded to query, source label and model prediction; they complete calibration batches, independent coding and third-party adjudication, with per-class agreement and Krippendorff's alpha reported.

Automatic exclusion is permitted only when the lower bound of the pre-specified one-sided 95% confidence interval for precision among predicted non_ai records is at least 99.5%, and recall for central AI-subject records is at least 98%. Failure in any required stratum blocks automation. Passing these gates creates deletion candidates only; physical deletion still requires a frozen manifest, checksums, an independent exclusion audit, a successful restore test and explicit approval. Retrieval recall is measured separately against an external country-year-language benchmark of known AI strategies, laws and reports.

Separate policy-eligibility axis

policy_eligibility_label uses eligible_national_policy, eligible_subnational_policy, eligible_igo_policy, government_linked_auxiliary, non_policy and unresolved. This decision uses document genre, issuer role, governmental relationship and policy function only after AI relevance has been assigned. Raw audit proportions from stratified samples are not reported as corpus composition without sampling weights and confidence intervals.

7. Determine document form and genre

This stage classifies physical information objects and document genre; it does not determine final policy eligibility. It excludes records that are confidently scholarly papers or patent documents from the derived policy-report corpus. It does not physically delete source files. Confirmed papers and patents are retained in separate AI-paper and AI-patent auxiliary corpora with their identifiers, metadata and collection provenance.

Independent classification axes

Before paper and patent separation, classify each object as a substantive document, non-document artefact, fragment or unresolved. Audio, video, images, isolated tables, folders, routine event notices and similar artefacts do not enter the policy-document corpus. Policy Commons artifact type alone is insufficient; scanned and OCR-poor official reports remain document candidates.

document_genre_normalised and policy_eligibility_label are decided separately. A document can have scholarly features but still be an official government-commissioned or adopted policy output. Conversely, a document hosted by a government or university is not automatically a policy report. Institution type alone never determines document genre.

Evidence for a scholarly paper

Automatic paper classification requires mutually consistent structured and content evidence. Strong signals include a journal or proceedings title, volume, issue, article pagination or article number, manuscript type, conference-paper metadata, scholarly DOI registration and an abstract organised around research questions, methods, results and discussion. A DOI, university publisher, research institute or the word “paper” alone is insufficient because official reports and working papers can share these features.

Patent classification uses jurisdiction-qualified publication identifiers and patent-specific metadata. Ordered decision procedure

  1. Verify that title, abstract, identifiers, publisher and URL passed the contamination and deduplication gates.
  2. Extract genre evidence from raw artifact type, bibliographic fields, identifiers, original document, publisher page and full text.
  3. Test patent evidence first because patent identifiers and claims are highly structured.
  4. Test scholarly-paper evidence using both bibliographic structure and document purpose.
  5. Check for formal government commissioning, co-issuance, adoption or official policy function before excluding a research-shaped document.
  6. Assign ambiguous or conflicting cases to review rather than forcing paper, patent or policy status.
  7. Route confirmed papers and patents to separate auxiliary corpora while preserving every source observation and exclusion reason.

Exclusion and audit controls

Each decision stores raw and normalised genre, rule ID, evidence fields and spans, identifier validation result, source URL, government relationship, model version, reviewer status and reason code. Automatic exclusion requires two compatible evidence families, such as structured bibliographic metadata plus document-content evidence. Title keywords, Policy Commons artifact type, publisher name or URL pattern alone cannot trigger exclusion.

Paper and patent exclusions are evaluated separately on a stratified frozen test set. Automatic removal from the policy master is permitted only when the lower bound of the pre-specified one-sided 95% confidence interval for precision in the relevant exclusion class is at least 99.5%. Failure for either papers or patents places that rule in review-only mode. “Removal” means exclusion from the derived policy corpus; physical deletion remains prohibited until the manifest, checksum, quarantine, restore-test and approval gates are satisfied.

8. Resolve institutions, roles and country concepts

An expert-reviewed method for identifying the countries and non-country actors that issue AI policy documents, using distinct-country whole counting.

Counting rule

Each document is attributed once to every distinct represented country of an eligible issuing institution. Multiple institutions from the same country still contribute one attribution for that country. No fractional weights or percentages are used.

Issuing institutionsAttribution
Two Korean public institutionsKOR = 1
Two Korean and one United States public institutionKOR = 1, USA = 1
Korean government and OECDKOR = 1, XIG = 1

Country totals are non-additive. A jointly issued document can appear once in more than one country, so the sum across countries can exceed the number of unique documents.

Attribution algorithm

  1. Extract candidate organisations from publisher, organisation-valued author, provider fields, the Policy Commons detail page and the original document.
  2. Separate issuer, publisher, distributor, repository, archive, host, commissioning body and adopting government.
  3. Resolve each issuer against a versioned institution authority table, including its exact legal entity and status at publication.
  4. Classify its role as sole issuer, co-issuer, commissioned contractor, adopting body, publisher only, host only or unresolved.
  5. Create one country-attribution row for every distinct eligible issuer jurisdiction.
  6. Apply UNIQUE(record_id, attribution_type, jurisdiction_code) so multiple issuers from one country are counted once.
  7. Assign policy jurisdiction separately. Commissioning or adoption does not convert a private contractor into a government issuer.

Publication country, issuer country, target country, author-affiliation country and policy jurisdiction remain separate variables. Raw CY, PP, PB and AU values are preserved as evidence.

  • A report that merely analyses Korea receives target_country = KOR, not a Korean issuer attribution.

Normalised data model

The source of truth is a document-country link table, not a semicolon-separated country cell. CTRY is populated as a scalar only when exactly one eligible jurisdiction exists. Multi-country analysis uses one document_country_link row per distinct eligible jurisdiction; XMU is never stored as an attribution row or country value.

Its core fields are record_id, attribution_type, jurisdiction_code, attribution = 1, inference method, evidence source, confidence, review status and decision version.

Separate document-institution links retain institution identity, issuer role and government relationship. The document table stores is_multi_country, issuer_country_count and attribution_method_version.

Reporting and quality assurance

Reports must show unique documents, country-attribution rows, multi-country documents, IGO records, EU records, multinational-private records and unresolved records separately. Before panel regression, country rows are aggregated to the intended country by topic by period grain.

Required table note. Counts use distinct-country whole counting. Jointly issued documents may appear once in more than one country; multiple issuers from the same country are counted once. Country totals therefore do not sum to the number of unique documents.

Automated checks reject duplicate document-country keys, reject XMU as an attribution row, prevent non-country codes from entering ISO-country totals, and prevent publication place or policy target from being copied into issuer jurisdiction.

Policy eligibility is decided only after AI relevance, document genre, issuer role, governmental relationship and policy function are resolved. A failure on one axis is never silently converted into failure on another.

Analytical dates and countries

Derive year_best, issuer-country links and policy jurisdiction only after identity, genre and institutional relationships are stable. Publication, enactment, effective, copyright, update and indexed dates remain typed fields. Country concepts remain separate: issuer country, target country, author-affiliation country and policy jurisdiction. Scalar CTRY is used only for a single eligible jurisdiction; multi-country attribution is represented by link-table rows.

10. Build and validate the local master

Build the local master in a new staging directory. Do not modify raw files or overwrite a prior release. Validate identity, AI relevance, genre, policy eligibility, institutions, countries and years separately on frozen test data grouped by document-version family.

  • Reconcile raw observations, parse quarantine, linked observations, canonical anchors, duplicate links, accepted records, exclusions, unresolved records and conflict quarantine.
  • Validate primary keys, foreign keys, cardinalities, idempotent reruns and checksum equality.
  • Report rule-specific performance, agreement and confidence intervals by language, period, issuer, evidence tier and genre.
  • Freeze a local release ID, manifests, checksums, code/configuration hashes and validation report before any iCloud integration.

Retrieval-recall gate. Coverage is tested against a benchmark constructed independently of Policy Commons search results and stratified by country, language, period, institution type and policy genre. A failed stratum triggers documented supplementary retrieval, a new frozen input snapshot and rerunning of affected stages. Recall is not generalised beyond benchmarked strata.

11. Freeze, process and reconcile the iCloud collection

  1. Inventory iCloud inputs independently, recording storage location, cloud provider, physical-file identity or content hash, hydration status and snapshot membership.
  2. Do not hydrate or process cloud-only inputs during Step 1; cloud processing begins only here.
  3. Apply Steps 2 to 9 to iCloud observations with the same frozen code, identifiers, normalisers and rule versions.
  4. Preserve the approved local release ID and reconcile into a new integrated snapshot rather than mutating the local master.
  5. Produce a crosswalk and counts for local-only, iCloud-only, matched, enriched, conflicted and unresolved records.

Identical copied files and filesystem aliases are distinguished: file occurrences retain paths and storage context, while unique byte objects are identified by content hash. The integrated staging snapshot is immutable and must pass the same gates as the local release.

12. Approve and release the integrated master

The final release is promoted atomically only after all stage ledgers reconcile and required thresholds pass. The release manifest records run and snapshot IDs, code commit, environment lock, parser/configuration/rule/model hashes, input-manifest hash, timestamps, random seed and reviewer-codebook version.

Release package. Canonical master, source observations and collection routes, field survivorship, duplicate and typed work relations, institution and country links, policy labels, paper and patent auxiliary corpora, non-AI and non-document exclusions, unresolved and quarantine tables, validation reports, checksums and reconciliation crosswalk.

Optional post-release deletion. Raw-source retention is the default. Physical deletion is a separate operation after publication and requires an approved deletion manifest, exact path and SHA-256, reconciled counts, recoverable quarantine, successful restore test, completed cloud synchronisation and a final path/size/time/hash recheck. Any change aborts deletion.
