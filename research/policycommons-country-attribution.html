Policy Commons curation protocol

Duplicate resolution, broad AI relevance screening and country attribution for country-level research.

Protocol 3.0 · implementation 3.0.3 · release_02 · updated 19 September 2026

Current status. Local source reprocessing and automated classification are complete. Release_02 contains 92,476 broad AI documents, including 12,415 ambiguous candidates. Its rule-based national issuer view contains 17,367 documents across 71 countries. Structural and source-integrity checks passed; human original-document validation remains pending. These figures are not a count of verified government policy reports. Additional iCloud collections have not been newly reconciled into this local release.

Scope and execution order

The analytical unit is a document version. A downloaded occurrence is a source observation. AI relevance, document form, institutional role and country relationship are separate classification axes. National and subnational bodies, public research institutes and qualifying private issuers may contribute to country-level analysis.

  1. Freeze inputs and configuration.
  2. Parse, normalise and check contamination.
  3. Resolve duplicates and select canonical metadata.
  4. Screen historical and multilingual AI relevance.
  5. Classify document form and genre.
  6. Resolve institutions and country relationships.
  7. Construct explicit analysis views using whole counting.
  8. Validate, reconcile local and iCloud data, and release a new version.

Process local inputs first, freeze that result, then process additional iCloud observations with the same configuration. Resolve aliases before inventorying because local and cloud paths may refer to the same file. Every stage writes new outputs, decisions and reconciled counts. Analytical exclusion does not require physical deletion.

Reading this page. Sections 1–8 describe the protocol, including required work that remains outstanding. The executed release record below distinguishes implemented rules, diagnostic checks and uncompleted validation. Storage in an iCloud-backed folder does not mean all iCloud source collections have been included or server synchronisation has been verified.

1. Freeze inputs and configuration

Create input_manifest.csv containing file ID, original and real paths, SHA-256, size, format, collection query/category, retrieval time and hydration status. Process identical file hashes once while preserving all paths and collection memberships. Unread cloud placeholders are incomplete inputs.

Freeze run_config.json with the following values and package the actual lookup tables alongside it.

run_id; protocol_version=3.0; input_manifest_sha256;
code_commit; environment_lock_sha256; normalisation_version;
ai_dictionary_sha256; country_aliases_sha256;
institution_authority_sha256; analytical_year_scope=[1990,2026];
validation_seed=20260919; validation_sampling_plan;
acceptance_thresholds_by_analysis; country_counting=whole_count

The analytical year scope does not remove older documents from the source archive. Record missing dates and out-of-scope dates explicitly.

2. Parse, normalise and check contamination

Derive an immutable observation ID from file hash and record ordinal. Preserve raw records and repeated fields. Extract identifiers, title, abstract or summary, keywords, publisher, authors, affiliations, language, genre, dates and URLs. Distinguish provider-generated summaries from original abstracts.

FieldRule
TextPreserve raw text; create Unicode NFKC and whitespace-normalised matching values. Record OCR uncertainty.
IdentifiersExtract every available namespaced ID independently. Normalise DOI prefixes and case; record syntax and resolution status separately.
URLsNormalise scheme and hostname case. Preserve case-sensitive paths and identifying query parameters. Remove only explicitly listed tracking parameters.
DatesPrefer publication date/year and verified primary dates. Never silently use retrieval or secondary dates. Store date type and evidence.
Missing yearConsult the original publication imprint or publisher page. A year mentioned in the title/body is only a candidate. Otherwise retain unresolved.

Check record boundaries and malformed fields, then check whether ID, title, abstract and issuer belong together. Valid RIS syntax does not establish semantic consistency. A confirmed shifted-field or mismatched-abstract pattern quarantines the affected batch until diagnosed and corrected.

Outputs Source observations, parsing errors, batch-quality decisions and quarantine records. Every source occurrence receives a disposition.

3. Resolve duplicates and select metadata

  1. Extract all PC IDs, DOIs and canonical URLs from all relevant fields. An unusable populated ID must not prevent extraction from another field.
  2. Create candidate pairs using shared namespaced identifiers. Title, publisher, year and language similarities generate review candidates only.
  3. Before merging, check title, issuer, language, publication date type, edition/revision and available abstract/content. Substantive conflicts block automatic merging. Missing values are not evidence of compatibility.
  4. Merge only the same document version. Keep translations, substantive revisions and annual editions separate with typed relations. Check every member of a proposed cluster; transitive links do not override conflicts.
  5. Rank canonical anchors by structural validity and core metadata completeness, followed by secondary completeness and a stable observation-ID tie-breaker. Abstract length alone does not establish quality.
  6. Fill missing fields only from accepted same-version records. Preserve conflicting non-empty values and the source of every selected field.

Outputs Canonical records, record-source links, match decisions, field provenance, document relations and prior-to-current ID crosswalks. Each accepted observation maps to one canonical record per release.

Checks Different editions remain separate; tracking-only URL changes may match; different document-identifying parameters remain distinct; compatible DOI-only and PC-ID records sharing a DOI become candidates. Evaluate both false merges and residual duplicates.

4. Screen historical and multilingual AI relevance

Screen title, abstract/summary and keywords. Enrich insufficient records from original documents where available and record the evidence. Collection-query membership is not an AI label.

Use one versioned dictionary for inclusion and protection against erroneous exclusion. Each entry records language, term, spelling/spacing/hyphenation variants, ambiguity class, context rule and rule ID. Preserve all matched spans and fields; do not classify from a truncated earlier match list.

Expand historical and multilingual expressions explicitly, including OCR line breaks and spacing variants. Do not assume one vocabulary characterises an entire decade. Rescreen the full recoverable canonical population, including previously excluded records, when the dictionary changes.

Store ai_relevance = confirmed | candidate | non_ai | insufficient_evidence and evidence_scope = central | application | incidental | unclear. Broad screening retains confirmed and candidate documents. A keyword in the title alone does not establish centrality.

Reassess the previous 430 exclusions using the unified dictionary and source evidence. Retain ambiguous cases for adjudication. Report recovered historical documents and changes to retained and excluded sets.

5. Classify document form and genre

Store content form, genre and institution type separately. A university can issue a policy report; a government portal can host a journal article.

  • Exclude standalone audio, video, images and tables from the document-analysis view. Scanned reports remain documents despite poor OCR.
  • Route clearly identified scholarly papers and patents separately using publication/identifier evidence.
  • Exclude logistical meeting notices, agendas and attendance lists. Retain substantive decisions, recommendations or policy reports produced through meetings.
  • Preserve uncertain genres with reason codes.

Country inference may cover all AI candidates. Apply genre eligibility again when constructing the analytical view so excluded genres do not re-enter through a country link.

6. Resolve institutions and country relationships

Identify issuer/co-issuer, publisher, contractor, commissioning/adopting body, author affiliation and host/repository roles. Resolve exact entities and publication-time jurisdictions where evidence permits. The institution authority table records aliases, type, jurisdiction, parent entity, validity dates, source and review status.

ConceptRequired evidence
issuer_countryIssuing/co-issuing entity and its jurisdiction. Publication place, language and title mentions alone are insufficient.
target_countryThe country is a substantive policy or issue subject, not merely an example or name occurrence.
publication_countryPublication-place metadata with provenance.
author_affiliation_countryIdentified author-affiliation relationship and institution jurisdiction.
language_country_signalIndirect language-derived candidate jurisdictions, potentially multiple.
policy_jurisdictionVerified governmental commission, adoption or territorial applicability.
  1. Audit inherited values. A country inferred through place_metadata remains publication country and cannot automatically become issuer country. Preserve the original inference chain.
  2. Extract country/subnational mentions as candidates. Prefer longest matching entities, suppress overlapping aliases and resolve ambiguous names through context. Otherwise retain uncertainty.
  3. Determine each candidate's relationship to the document or institution. Store country mentions before confirming target-country links. One or two mentions do not prove policy relevance.
  4. Use language to prioritise investigation and corroborate evidence. Shared languages yield multiple candidates. Unsupported language codes must not be ignored to create false certainty. Translation alone creates no baseline country attribution.
  5. Retain every evidence reference, relationship, method, rule version and review status. Do not take the maximum confidence across unrelated evidence types.

International and multinational issuers

Attribute OECD and other global publications to the organisation, not its headquarters country. A verified local-office issuer can receive a national issuer link. A headquarters report substantively about a country may receive a target-country link. “Country programme” in a title does not prove local issuance.

For KPMG, BCG, Deloitte and similar firms, resolve the actual national legal entity or issuing office. A brand, headquarters address or language is insufficient. A government commission creates separate policy-jurisdiction evidence without converting a contractor into a government issuer.

Use ISO alpha-3 codes under a frozen territorial convention. Preserve international actors separately, for example XIG, XEU and XMN. Unresolved and “multiple” flags are not country rows.

Required counterexamples North Korea must not map to South Korea; Northern Ireland must not additionally map to Ireland; New Mexico must not additionally map to Mexico; Victoria, British Columbia must not imply Australia; American Indian must not imply India. A French translation of a Canadian report creates no French issuer link. Swiss publication place with an unknown issuer leaves issuer country unresolved.

Institutional classes include central government, parliament/regulator, subnational government, public research, private research/think tank, other private issuer, international organisation and unresolved. These classes support comparison and do not substitute for relevance evidence.

typed links: UNIQUE(record_id, attribution_type, jurisdiction_code)
analysis view: filter AI, form/genre, relationship and review status
              distinct(record_id, jurisdiction_code)
              attribution = 1

One qualifying document linked to Korea and the United States contributes one to each. Two Korean issuers still contribute one to Korea. Use no percentage shares. Multilingual does not mean multinational. Report unique document counts and document-country counts separately.

8. Validate, reconcile and release

  1. Pass fixed counterexample tests for identifiers, edition compatibility, alternative AI meanings, geographical ambiguity, global issuers and whole counting.
  2. Freeze a validation sample before tuning. Include retained and excluded records and duplicate candidates, stratified by period, language, institution, rule and missingness. Save the sampling frame, seed, inclusion probabilities and IDs. Oversample rare historical/ambiguous cases and use sampling weights for population estimates.
  3. Use two independent coders, source evidence and adjudication. Label AI-assisted reviews explicitly. Review all 430 prior exclusions.
  4. Report duplicate false merges and residual duplicates, AI precision/recall, issuer and target accuracy/coverage, unresolved rates and coder disagreement, with 95% confidence intervals. Recall requires examining excluded records too. Checksum agreement does not measure accuracy.
  5. Freeze acceptance thresholds appropriate to each analysis before validation. Unvalidated rules remain candidate rules. A quality target is not an achieved result.
  6. Freeze the local master, process additional iCloud observations using the same rules, then reconcile through the same duplicate procedure while retaining all collection memberships.
  7. Write a new versioned release with stage counts, change log, unresolved issues, permitted views and checksums.

Canonical records retain ID, year/date provenance, title, abstract/summary, keywords, language, publisher, authors, affiliations, URLs and classification labels. Evidence tables preserve full source references, rules and statuses. Require unique IDs, valid foreign keys, unique typed links, weights equal to one and a disposition for every observation.

Reproduction requires frozen inputs, executable code, dictionaries, authority tables and an environment lock. This page is a reproducible-process specification; it is not an executable data package.

What the executed rules establish

The AI master includes historical expressions, multilingual terms and ambiguous candidates. The expanded pass recovered 8,014 broad records outside the previous retained-ID mapping, including 330 records dated in the 1990s. This is not a net increase or a recall estimate. The earlier 84,438 retained records and 300,555 canonical groups were products of different rules. Likewise, the earlier 406,029 observation count included repeated identical-file occurrences, whereas 390,910 counts observations after file-content deduplication.

The basic national issuer view requires ai_relevance=confirmed, document_genre=document, a year in 1990–2026, no quality-review flag and a source-supported or rule-supported issuer-country link. Here confirmed denotes an automated AI rule, not human adjudication. Institution-name rules can still misidentify an entity or its role. This view measures inferred issuing activity, not verified government authorship or endorsement.

Publication place, language, author-affiliation mentions and country mentions remain separate evidence. Unverified mentions were not promoted to substantive target-country links. A multi-country institution name does not establish co-issuance. Each qualifying distinct country receives weight 1, but this release's basic view has one supported issuer country per document; the equality of document and country-row counts does not validate the completeness of co-issuer extraction.

Diagnostic corrections and verification

  • Two independent AI agents assessed a purposeful 60-record metadata sample. Their AI labels agreed on all 60 records. The sample was used to revise rules and is neither a representative accuracy estimate nor a held-out validation set.
  • Corrections covered New South Wales versus Wales, case-based reasoning and trained pattern recognition, publisher names that were only places, technical-paper genre review, acknowledgement text in abstract fields and host-versus-issuer ambiguity.
  • All 20 fixed counterexample tests and four diagnostic regression checks passed. Unique record IDs, foreign-key membership, unique typed country links, whole-count weights and analysis-view filters passed structural assertions.
  • All 4,001 distinct source-file hashes were unchanged. No source was physically deleted. Hash consistency establishes preservation, not semantic correctness.
  • The previous 430 exclusions were reassessed by the expanded rules. Human original-document adjudication of those records remains outstanding.
